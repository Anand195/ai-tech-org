# GitHub Pages Publisher

Maintains a living, per-phase walkthrough site for every project so humans (and future agents) can track exactly what happened and why.

## When to Use
- After `phase-advisor` closes a phase.
- Whenever the project's documented progress needs publishing.

## Output
Writes into the project's `docs/` (GitHub Pages source):
```
docs/
  index.md            # project overview + phase index (auto-updated)
  _config.yml         # Jekyll config (theme, title)
  architecture.md
  deployment-guide.md
  phases/
    phase-1.md
    phase-2.md
    ...
  assets/             # diagrams, screenshots
```

## Phase Walkthrough Page Template
`docs/phases/phase-[N].md`:
```markdown
---
title: "Phase [N] — [Phase Name]"
date: DD-MM-YYYY
---

# Phase [N]: [Phase Name]

## What we built
[concrete deliverables, with links to code/PRs]

## Why
[the reasoning + decisions made — pull from decision-logger]

## Impact
[what this enables / improves / de-risks]

## Quality & Deployment
- Tests: [status] | Security scan: [status] | ship-gate: [PASS/FAIL]
- Deployment readiness: Docker [✅] Helm [✅/❌] k8s [✅/❌]

## Architecture at end of this phase
[mermaid diagram or link to architecture.md]

## Issues opened / resolved this phase
[link to git-issue-maintainer output]

## Next phase plan
Phase [N+1]: [what's coming + why]

---
*Generated by ScaleSync ai_tech_org_plugin · github-pages-publisher*
```

## index.md (auto-maintained phase index)
Keep a table linking every published phase with date + status.

## Workflow
1. Pull phase data from `phase-advisor` report + `decision-logger`.
2. Generate/update the phase page + index.
3. Ensure `_config.yml` exists (theme: minima or just-the-docs).
4. Stage docs changes; hand to `git-update-tracker` to commit/push.
5. Confirm GitHub Pages is enabled on the repo (gh CLI: check Pages settings; if off, instruct human to enable `docs/` as source — do not flip repo settings without approval).

## Behavior
- Use `gh` for any GitHub API actions; never hardcode tokens.
- Publishing is outward-facing → confirm with human before first publish per project (AOP).

## Standing Rules
- Every phase → one walkthrough page. The site tells the whole project story.
- Repo: github.com/Anand195/[project] (private; Pages can be private on supported plans).
- See [[phase-advisor]], [[git-update-tracker]], [[decision-logger]], [[technical-writer]].
